# Documentation

- `specifications/`: Feature requirements, behavior definitions, and design decisions.
- `guides/`: Usage guides, integration instructions, and migration notes.
- `api/`: Explanations of public APIs, their intent, and usage boundaries.

Keep implementation details in source code and tests. Use these documents for information that helps users and contributors understand how the package should be used or evolve.

The package exposes `Attributed` as its primary facade, with `AttributedCore` and `AttributedUtility` available for lower-level integrations.
